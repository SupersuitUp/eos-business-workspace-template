# Core Processes

The documented way the work actually gets done. One file per Core Process.

## Naming Convention

`<process-slug>.md` (kebab-case). Examples:

- `customer-onboarding.md`
- `sales-pipeline.md`
- `financial-close.md`
- `hiring.md`
- `customer-support.md`

## Which Processes to Document First

Wickman: 6-10 Core Processes per company total. Document the top 3 first (most broken or most leverage-bearing). Then add the rest over months 5-6 of an EOS rollout.

Common top 3: Sales, Customer Onboarding, Financial Close.

## The Three-Step Methodology

1. **Write the steps.** 7-15 steps. Decision points explicit. Responsible party noted.
2. **Test and refine.** Hand to someone outside the process; note every place they get stuck. Fix.
3. **Simplify.** Cut to one page. Use icons, arrows, hand-off markers.

## How to Add a New Core Process

Use the `eos-document-core-process` skill, passing the process name and an SME to interview. Output goes here.
